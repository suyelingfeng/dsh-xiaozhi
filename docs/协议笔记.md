# 协议笔记：小智 MCP 接入点

这些帧是对着 `wss://api.xiaozhi.me/mcp/?token=…` **实测抓下来**的，不是抄文档——
这个接入点没有公开的协议说明页，方向还特别容易搞反。留作以后对照。

## 1. 方向：我们是服务端

连上以后，**服务端先开口**：

```
<- {"id":0,"jsonrpc":"2.0","method":"initialize",
     "params":{"protocolVersion":"2024-11-05",
               "capabilities":{"sampling":{},"roots":{"listChanged":false}},
               "clientInfo":{"name":"xz-mcp-broker","version":"0.0.1"}}}
```

`clientInfo.name` 是 `xz-mcp-broker` —— 对面是 **MCP 客户端**，我们是 **MCP 服务端**。
所以：

- 我们要回 `initialize` 的 result，而不是发它；
- 工具清单由我们给；
- 用户说话时它才发 `tools/call`。

## 2. 完整握手

```
<- initialize                          (id 0)
-> {"jsonrpc":"2.0","id":0,"result":{
     "protocolVersion":"2024-11-05",
     "capabilities":{"tools":{"listChanged":false}},
     "serverInfo":{"name":"deepseek-harness","version":"0.2.0"},
     "instructions":"…"}}
<- {"jsonrpc":"2.0","method":"notifications/initialized"}
<- {"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}
-> {"jsonrpc":"2.0","id":1,"result":{"tools":[…]}}
<- {"jsonrpc":"2.0","id":2,"method":"ping","params":{}}
-> {"jsonrpc":"2.0","id":2,"result":{}}
```

要点：

- `protocolVersion` 原样回它请求的那个（实测就是 `2024-11-05`）；我们的实现是
  「有就用它的，没有就用默认」。
- `instructions` 是可选的，会被拼进对面的系统提示——放一句「回复用中文、简洁」很值。
- `tools/list` 只在**连接建立时拉一次**。改了工具要重启 DSH 并让小智重连。
- `ping` 大约**每 30 秒**一次。回 `{}` 就行；不回会被判死。
- 我们自己不从这条连接发请求（不发 `sampling`、不发 `roots/listChanged`）。服务端也没有
  向客户端推送的通道，所以「DSH 干完活主动播报」在这条路上做不到。

## 3. tools/list 的形状

```jsonc
{
  "tools": [
    {
      "name": "dsh_status",                    // ^[a-zA-Z0-9_-]{1,64}$
      "description": "…中文，写清什么时候用它…",
      "inputSchema": {                         // 标准 JSON Schema，不是 DSH 的 parameters 格式
        "type": "object",
        "properties": { "limit": { "type": "integer", "description": "…" } },
        "additionalProperties": false
      }
    }
  ]
}
```

注意别把 DSH 的 `defineTool({ parameters: {…} })` 那套直接搬过来——两个 schema 方言不一样。
本插件只给小智用，所以**没有**往 DSH 注册工具（`ctx.tools.register` 一次都没调），
避免污染 DSH 自己的模型。

## 4. tools/call 与返回

```jsonc
// 请求
{"jsonrpc":"2.0","id":7,"method":"tools/call",
 "params":{"name":"dsh_status","arguments":{}}}

// 成功
{"jsonrpc":"2.0","id":7,"result":{"content":[{"type":"text","text":"…"}]}}

// 业务失败：用 isError，而不是 JSON-RPC error（这样对面的模型能看到原因）
{"jsonrpc":"2.0","id":7,"result":{"content":[{"type":"text","text":"出错了：…"}],"isError":true}}
```

协议级失败（未知工具、未知方法）才用 `error`：

| 情况 | code |
|---|---|
| 未知工具 | `-32602` |
| 未知方法 | `-32601` |
| 内部异常 | `-32603` |

## 5. 我们实现的方法

| method | 处理 |
|---|---|
| `initialize` | 回协议版本、`capabilities.tools`、`serverInfo`、`instructions` |
| `notifications/initialized` | 记一个 `ready` 标志 |
| `ping` | 回 `{}` |
| `tools/list` | 11 个工具 |
| `tools/call` | 分发到对应实现，25 秒超时 |
| `resources/list`、`resources/templates/list`、`prompts/list` | 回空数组 |
| `logging/setLevel` | 回 `{}` |
| `completion/complete` | 回空 `values` |
| 其它 | `-32601` |

## 6. 连接行为

- **单连接**：同一个 token 只允许一条。第二个连接会把第一个顶掉（所以调试脚本用完要关）。
- 断线后按 1s → 30s 指数退避 + 20% 抖动重连，`state.json` 的 `reconnects` 会涨。
- 没有应用层心跳：我们只被动回 `ping`。真实断线靠 TCP 与对面的 ping 超时发现。
- 关闭帧里的 code 很关键：`4001` 一类通常表示 token 无效或过期。

## 7. 怎么自己复现

```sh
node test/live.mjs      # 连真实接入点，打印每一帧，46 秒后自己退出
```

它用假 ctx 演 DSH，所以不需要启动 DSH，也不会动你的会话；跑完一定要让它退出，
否则它占着那条唯一的连接。
