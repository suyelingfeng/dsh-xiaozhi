# 接入手册

从零把 DeepSeek Harness（下称 DSH）接到小智的 MCP 接入点，并让语音能看、能派活、能批审批、
能答问题。这份手册按「小智侧 → DSH 侧 → 验证 → 排障」的顺序写；协议细节见
[协议笔记](协议笔记.md)，用到的 DSH 内部接口见 [宿主 API 笔记](宿主API笔记.md)。

---

## 0. 它到底是怎么接的

先把方向摆正，这是最容易搞反的一步：

```
小智云端 (xz-mcp-broker, MCP 客户端)
        │  ① 我们主动连出去：wss://api.xiaozhi.me/mcp/?token=…
        │  ② 它发 initialize，再发 tools/list
        │  ③ 用户说话时它发 tools/call
        ▼
DSH 主进程内的本插件 (MCP 服务端)
        │  直接调用 DSH 自己的服务
        ▼
Session 控制器 / 审批水位事件 / 提问水位事件 / 后台作业
```

所以：

- **我们是 MCP 服务端**，工具由我们在 `tools/list` 里交给小智；
- 插件跑在 **DSH 主进程里**（不是旁路进程），因此不需要第二份 harness，也不需要去抓
  DSH 的 HTTP 令牌——审批、提问这些是进程内的水位事件，只有同进程的插件才接得住；
- 接入点 **同一时间只允许一条连接**：别的地方再连同一个 `token`，会把它顶掉。

## 1. 小智侧：拿到接入点地址

### 1.0 设备端不用动

设备跑的是 [xiaozhi-esp32](https://github.com/78/xiaozhi-esp32) 系固件（例如
[progyuan/xiaozhi-esp32-ai-robot](https://github.com/progyuan/xiaozhi-esp32-ai-robot)，
MIT，上游是 `78/xiaozhi-esp32`）。它只通过 WebSocket / MQTT+UDP 连**小智云**，不直连 DSH：

```
设备 ──▶ 小智云（智能体 + LLM）──▶ MCP 接入点 ──▶ 本插件 ──▶ DSH
```

所以**固件一行都不用改**，你要做的只是配网、绑定设备，然后在本仓库这边接上接入点。
换板子、换固件、换机器人都不影响这一侧。

1. 打开小智控制台，进入你这个智能体（agent）的配置；
2. 找到 **MCP 接入点**，创建一个，复制形如
   `wss://api.xiaozhi.me/mcp/?token=<一长串 JWT>` 的地址；
3. 这条 URL 里的 `token` 是签过名的 JWT，带 `exp` 过期时间。过期后只能重新生成一条，
   旧的连不上——插件会一直重连、`state.json` 里 `lastError` 会显示
   `closed (4001 …)` 之类的代码。

> token 等于「谁都能以你的身份连这个接入点」。别贴进聊天、别提交进仓库。
> 本仓库的做法：`cordis.patch.yml` 里 `endpoint` 留空；真值要么放 profile 的补丁层、
> 要么放 `~/.dsh/xiaozhi/endpoint`（见第 3 节）。

## 2. DSH 侧：装插件

插件是一个标准的 DSH 插件包（`dsh-xiaozhi`），有两种装法。

### 2.1 链接安装（改代码方便，推荐本地开发）

在 `~/.dsh/profiles/desktop/package.json` 里加两处：

```jsonc
{
  "dependencies": {
    "dsh-xiaozhi": "link:D:/path/to/dsh-xiaozhi"   // ← 换成你克隆下来的路径
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "@deepseek-ai/dsh-web-app",
        "…",
        "dsh-xiaozhi"                       // ← 让它的 cordis.patch.yml 生效
      ]
    }
  }
}
```

再建链接（等价于 `pnpm install` 对 `link:` 依赖做的事）：

```js
// node -e 里执行；两个路径都换成你自己的
fs.symlinkSync('D:/path/to/dsh-xiaozhi', '~/.dsh/profiles/desktop/node_modules/dsh-xiaozhi', 'junction')
```

或者干脆在 profile 目录跑一次 `pnpm install`。

### 2.2 包安装

```sh
npm pack                                    # 得到 dsh-xiaozhi-0.2.0.tgz
dsh plugin --profile desktop add ./dsh-xiaozhi-0.2.0.tgz
# 或者：DSH 设置 → 插件 → 添加 .tgz
```

同样要确认 `dsh.profile.bundles` 里有 `dsh-xiaozhi`（设置里的插件管理器通常会代劳）。

> **插件不会热重载。** 改完 `index.js`、改完配置，都要重启 DSH 才生效。

## 3. 放配置（含 token）

两层补丁的组合顺序是：先 bundle 层（本仓库的 `cordis.patch.yml`），再 profile 层
（`~/.dsh/profiles/desktop/cordis.patch.yml`），最后才是命令行 `--patch`。
profile 层的 `config` 会**整条替换** bundle 层那一条，所以下面要把字段写全。

### 3.1 方式 A（推荐）：地址放本地文件

把接入点地址写进 `~/.dsh/xiaozhi/endpoint`，一行一条，`#` 开头是注释：

```sh
# Windows 上权限位不生效，靠「不在仓库、不在 YAML」来隔离
printf '%s\n' 'wss://api.xiaozhi.me/mcp/?token=…' > ~/.dsh/xiaozhi/endpoint
```

**`endpoint` 配成空**，插件启动时会去读这个文件：

```yaml
- id: xiaozhi
  name: dsh-xiaozhi
  config:
    endpoint: ""            # ← 空：去 ~/.dsh/xiaozhi/endpoint 读
    allowControl: true
    approvals: auto
    questions: auto
```

好处：profile 的 `cordis.patch.yml` 是会被截图、贴进 issue、甚至提交到别处的文件，
地址（也就是 token）不该住在里面。`state.json` 里只会显示 `endpointSource: "file"`，
不会回显地址本身。

### 3.2 方式 B：直接写在 profile 补丁里

把 [`cordis.local.example.yml`](../cordis.local.example.yml) 的内容追加进
`~/.dsh/profiles/desktop/cordis.patch.yml`，填上真实 endpoint：

```yaml
- id: xiaozhi
  name: dsh-xiaozhi
  config:
    endpoint: "wss://api.xiaozhi.me/mcp/?token=…"
    allowControl: true
    approvals: auto
    questions: auto
    approvalGraceMs: 20000
    voiceWindowMs: 1800000
```

配了 `endpoint` 就以配置为准（`endpointSource: "config"`），不会再读文件。

### 3.3 配置项全表

| 字段 | 默认 | 含义 |
|---|---|---|
| `endpoint` | 空 | 接入点 URL（含 token）。空 = 读 `~/.dsh/xiaozhi/endpoint`；那里也没有就不连接 |
| `token` | 空 | 想单独放 token 时用；URL 里已带 token 就不用填 |
| `allowControl` | `true` | `false` = 只读：看状态/会话/对话，不能发消息、停止、批审批、开新会话 |
| `approvals` | `auto` | 审批接管策略：`auto` / `always` / `off` |
| `questions` | `auto` | 提问接管策略：`auto` / `always` / `off`（`off` 仍保留超时补答） |
| `approvalGraceMs` | `20000` | 等语音回答的时长；超时交回 DSH 的卡片 |
| `voiceWindowMs` | `1800000` | 语音「算数」的时间窗（30 分钟）；`auto` 策略靠它判断你在不在用语音 |
| `reconnectMinMs` / `reconnectMaxMs` | `1000` / `30000` | 断线重连的指数退避区间 |

## 4. 工具清单

工具名和描述是给小智的模型看的，所以描述写成了中文，并带「用户说什么时用它」。

| 工具 | 作用 | 语音例句 |
|---|---|---|
| `dsh_status` | 是否在跑、跑哪个会话、最近一条回复、今日用量 | 「DSH 在干嘛？」「好了吗？」 |
| `dsh_list_chats` | 最近的会话（标题 + 最后活动） | 「我最近都让它干了啥？」 |
| `dsh_read_conversation` | 读某会话最近几条对话（你、DSH、工具调用） | 「刚才那个对话它回了什么？」 |
| `dsh_send_message` | 把一句话发给 DSH | 「告诉 DSH：把测试跑一遍」 |
| `dsh_stop` | 停掉正在跑的任务 | 「停，别做了」 |
| `dsh_pending` | 谁在等你：待批请求 + 等你答的问题（带选项） | 「有要我处理的吗？」 |
| `dsh_answer` | 放行/拒绝审批，或回答问题 | 「允许」「选第二个」 |
| `dsh_jobs` | 正在跑的后台任务 | 「后台在跑什么？」 |
| `dsh_job_kill` | 停掉一个后台任务 | 「把那个 pnpm test 停了」 |
| `dsh_new_chat` | 在指定文件夹开新会话并派活 | 「在 D:\foo 开个新会话，跑测试」 |
| `dsh_ui_open_session` | 把界面切到某个会话 | 「打开刚才那个会话」 |
| `dsh_ui_panel` | 回到对话 / 打开桥接面板 | 「回到对话」「打开桥接面板」 |
| `dsh_ui_sidebar` | 展开或收起左侧栏 | 「收起侧栏」 |
| `dsh_diagnostics` | 排障用的原始信息 | （平时不用） |

`session` 参数都可以省略，默认是「最近活跃的会话」；也可以填会话 ID、标题片段，或它所在
文件夹名（比如 `MCPzhi`）。

## 5. 三种「它在等你」

DSH 里三件事都会把轮次挂起等你，插件分别接管：

### 5.1 审批（`approval/request`）

执行命令、写文件、联网前，DSH 会发一个水位事件问你。谁先答谁算数：插件接了，就能用语音
答；插件不接，DSH 自己的审批卡片立刻弹出。

### 5.2 提问·前台（`user-questions/request`）

`ask_user_question` 会走另一个水位事件，默认由客户端（GUI 的答题卡）来接。插件把监听
`prepend` 到最前面，先压住请求，等你说答案。

### 5.3 提问·超时补答（`userQuestions` 投影）

问题超时后不会消失，会留在会话的 `userQuestions` 投影里（`state: continued`）。
插件把这类也列进 `dsh_pending`，用 `userQuestions.answer(agent, callId, { answers })`
补答——答案会作为一条 `user-question-reply` 消息被推给 agent，问题就接上了。

**所以哪怕问题在你没开语音时超时了，回头一句话也能补上。**

### 5.4 `auto` 的取舍（重要）

`auto` 的判断是：**最近 `voiceWindowMs`（30 分钟）内，你用语音驱动过 DSH**（发过消息、
开过新会话，或者小智调过工具）→ 才让语音先接。否则请求直接交给 DSH 自己的卡片。

这样：

- 一直坐在电脑前敲键盘的人，卡片行为**完全不变**；
- 走开之前用嘴交代过活的，这半小时内的东西会先问语音；
- 语音这 20 秒没答，请求原样交回 DSH，卡片照常弹出——**不会丢，也不会卡死**。

代价是：在语音时间窗里，审批卡/问题卡最多会晚 `approvalGraceMs`（20 秒）出现。
觉得烦就把 `approvals`/`questions` 改成 `off`，或者把 `voiceWindowMs` 调小。

## 6. 验证

### 6.1 看状态文件

重启后插件每 10 秒写一次 `~/.dsh/xiaozhi/state.json`：

| 字段 | 正常值 | 说明 |
|---|---|---|
| `plugin` | `dsh-xiaozhi@0.2.1` | 确认加载的是哪一版 |
| `pid` | 数字 | 插件所在进程（DSH 主进程） |
| `connected` / `ready` | `true` | 有没有连上接入点、握手完成没有 |
| `endpointSource` | `file` / `config` | 地址是从本地文件读的，还是配置里写的（不回显地址本身） |
| `protocol` | `2024-11-05` | 协商出来的 MCP 版本 |
| `reconnects` | 小 | 重连次数；一直涨说明 token 过期或网络问题 |
| `lastError` | 空 | 断线原因，比如 `closed (4001 …)` |
| `socketSupport` | `true` | 运行时有没有全局 WebSocket |
| `listError` | 空 | 会话列表读取失败的原因（字段名对不上时会写这里） |
| `sessionCount` / `sessions` | 你那几个会话 | 插件读到的会话；`title`/`cwd`/`running`/`blank` 都在 |
| `calls` | 随使用增长 | 小智调用工具的次数 |
| `approvals` / `questions` | `[]` | 当前压着、等你用嘴答的东西；`state: handed-over` = 已交回界面 |

### 6.2 一次冒烟

1. 说「DSH 现在在干嘛」→ `state.json` 的 `calls` +1；
2. 说「在 D:\某个目录开个新会话，列一下目录」→ 应该提示新会话已开工；
3. 让它干点要审批的活（比如写文件），立刻说「有要我处理的吗」→「允许」；
4. 让它用 `ask_user_question` 问你一件事（比如「先跑单元测试还是集成测试」），
   在 20 秒内说「第二个」；`state.json` 的 `questions` 里那条应该从 `open` 走到 `answered`。

### 6.3 界面里的面板

插件还带一个浏览器侧的一半（`client.js`），装的时候随包走，不需要额外配置：

- **底栏**：界面底部多一条 26px 的细条「● 小智桥接 · 已连接 · N 次调用」，有待处理时标出数量；
- **面板**：点底栏打开，显示协议、地址来源、重连次数、最后错误，以及待批请求（允许/拒绝）和
  待答问题（选项 + 输入框）；面板里还有「刷新 / 重新连接 / 关闭」。

它和 GUI 自己的 API 走同一条通道（`POST /api/xiaozhi`，cookie 认证；桌面端经 IPC 桥接），
不开新端口、不做独立认证。面板读不到的字段以 `state.json` 为准。

> 客户端一半必须重启 DSH 才会加载。若底栏没出现，看 **设置 → 插件 → 插件列表** 里
> `dsh-xiaozhi` 有没有「同步失败」——那通常是 bundle 语法或 `ctx.slots` 名称对不上，
> 把那条错误文本发我即可。

### 6.4 用嘴控制界面

同一个面板通道也用来下发命令：`dsh_ui_open_session` / `dsh_ui_panel` / `dsh_ui_sidebar`。

- 宿主把命令放进面板的状态轮询（2 秒一次），浏览器执行完回一个 ack；
- 所以工具的回答是**真的**：切过去了才说「已经切到」，界面拒了会带回原因
  （比如 `this shell has no layout.selectPanel`），4 秒没人接就明说「没收到确认」；
- `allowControl: false` 时这些命令同样被拒，和发消息、批审批一条线。

延迟上限就是那个轮询间隔（2 秒）加一次往返——语音场景够用，但不是「瞬间」。

## 7. 排障

| 现象 | 先看 | 常见原因 |
|---|---|---|
| `connected: false`，`reconnects` 一直涨 | `lastError` | token 过期；或者别处连了同一个接入点把它顶掉 |
| 小智说没有这些工具 | `state.json` 的 `plugin` | 插件没加载（bundles 里漏了）；或者小智侧工具列表是连接建立时拉的，刷新一次 |
| `sessionCount: 0` | `listError`、`sampleKeys` | 这一版 DSH 的 `list()` 签名变了；把 `sampleKeys` 发我，按字段名改 |
| 审批卡迟迟不弹 | `approvals` 数组 | 你在语音时间窗里，最多压 `approvalGraceMs`；或改成 `off` |
| 说了「允许」没反应 | `approvals` 是否为空 | 已经被交回界面（`handed-over`），或者 id 对不上 |
| 回答问题没进 DSH | `questions` 数组 | 前台接管没生效（客户端先接了）；等它超时后走「补答」那条路 |
| `dsh_ui_*` 说「没收到确认」 | 底栏是否可见 | 界面没开；或客户端那一半没加载（设置 → 插件 → 插件列表） |
| `dsh_ui_*` 说「界面没能执行：…」 | 括号里的原因 | 那版 shell 没有对应方法；把整句发我 |
| 插件加载失败、DSH 报错 | DSH 的日志窗口 | 语法错误；`node --check index.js` 先过一遍 |

## 8. 安全边界

- **不要把语音接到「改权限预设」上**：只读 / 可写 / 完全访问这种开关，误识别一次就是事故；
- **不要给语音一个「直接跑 shell」的工具**：DSH 自己的工具带沙箱和审批，绕过它等于拆掉闸门；
- `allowControl: false` 是唯一的总闸：只读时所有写操作（发消息、停止、批审批、开新会话）都会拒绝；
- 接入点 token 泄漏 = 别人能以你的身份连这个 agent。它的权限边界就是上面这些工具；
- 插件只在本地跑，不监听端口、不写网络服务，唯一的出站连接就是你配置的那条 wss。

---

## 9. 卸载

1. 从 profile 的 `dsh.profile.bundles` 里删掉 `dsh-xiaozhi`，从 `dependencies` 里删掉那条链接；
2. 删 `~/.dsh/profiles/desktop/node_modules/dsh-xiaozhi` 与 profile 里那条 `id: xiaozhi` 的配置；
3. 重启 DSH，顺手删 `~/.dsh/xiaozhi/`。

只想临时停用：在 profile 补丁里给那条 entry 加 `disabled: true`，重启即可，代码和链接都留着。
